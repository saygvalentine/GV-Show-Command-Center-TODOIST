## Phase 2 goal

Implement automatic local-to-Todoist sync for show tasks and e-blasts through the existing durable `todoist_sync_events` outbox.

Target flow:

local create/update/complete/reopen/delete
→ local DB mutation plus durable/coalesced outbox intent
→ immediate bounded delivery attempt during the active request
→ mark delivered or pending/failed
→ never fail the local user action merely because Todoist is unavailable

## Fixed product rules

1. Scope:
   - Sync show tasks and e-blasts only.
   - Do not sync Office Tasks.

2. Todoist project:
   - Both tasks and e-blasts use the configured shared project.
   - Always read project routing from server-side `todoist_settings`; never from frontend state/localStorage.

3. Eligibility:
   - A local task or e-blast with a due date is eligible for Todoist.
   - Due dates may be past, today, or future.
   - A local task/e-blast with no due date has no Todoist representation.
   - If a due date is removed from a linked item, queue a remote Todoist delete/unlink.
   - Do not create a Todoist item for an undated local record.

4. Identity:
   - Use `tasks.todoistTaskId` and `eblasts.todoistTaskId` as the only remote identity mapping.
   - Never match Todoist tasks by title/content.
   - Todoist content and description are presentation/context only.

5. Operations:
   - Local create with due date → create/upsert in Todoist.
   - Local title/notes/due-date update → update/upsert Todoist task.
   - Local completion/reopen → close/reopen Todoist task.
   - Local sent/unsent e-blast state → close/reopen Todoist task.
   - Local delete → durable remote delete request.
   - Due date cleared → durable remote delete/unlink request.

6. Failure/retry:
   - Local save must succeed even if Todoist delivery fails.
   - Use `todoist_sync_events`, not `todoist_orphans`, as the new durable outbox.
   - Coalesce one active event per item using the existing partial unique indexes.
   - No `setInterval`, polling loop, permanent worker, cron, or background process.
   - Immediate delivery attempt can occur after local DB transaction commit.
   - Future retry options are request-triggered, explicit repair-triggered, or separately approved low-frequency scheduled HTTP trigger.
   - Do not silently create duplicate Todoist tasks on retries.

7. Remote deletion policy:
   - Phase 2 is local-to-Todoist only.
   - Do not add webhook/inbound Todoist logic.
   - Reserve future remote-deletion unlink handling for Phase 3.
   - Do not introduce automatic recreation logic based on a remote 404 beyond an explicitly defined local delivery policy.

8. Legacy/manual path:
   - Keep manual Push-to-Todoist UI and POST /api/export/todoist/sync working during Phase 2.
   - Extract shared per-item delivery logic so manual sync and automatic outbox delivery do not diverge.
   - Correct the existing manual-sync counter bug only if it can be fixed within the shared delivery extraction without expanding scope.
