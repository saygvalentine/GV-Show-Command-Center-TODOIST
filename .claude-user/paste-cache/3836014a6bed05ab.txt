Why this is required:

The Todoist context uses the React Query settings cache to construct complete replacement documents. If request 1 is sent first, request 2 is sent second, and request 1’s response arrives last, a blind onSuccess cache replacement from request 1 can overwrite newer optimistic/request-2 state. That can cause a later user interaction to resend stale configuration to the server.

Implement a minimal latest-mutation guard inside TodoistProvider.

## Required behavior

Use a monotonic mutation sequence/version held locally in TodoistProvider, for example with `useRef`.

For every settings mutation:

1. Allocate a sequence number when the mutation begins.
2. In `onMutate`:
   - Record the previous cached settings document.
   - Optimistically write the complete outgoing settings document to the settings query cache.
   - Return mutation context containing:
     - `previous`
     - `sequence`
     - any other minimal data needed.

3. In `onSuccess`:
   - Update the React Query settings cache with the server response only if this mutation’s sequence is still the latest started mutation.
   - If the response belongs to an older mutation, do not let it overwrite newer cached state.

4. In `onError`:
   - Roll back only if this failed mutation is still the latest started mutation.
   - Do not let an older failed mutation roll back a newer optimistic change.
   - If a latest-mutation failure cannot safely restore a known current state, invalidate/refetch the settings query rather than overwriting newer data.

5. Preserve all current requirements:

   - The context public interface remains unchanged.
